# 일본어 댓글 고르기 (굿바이브 댓글 오버레이)

굿바이브 하단에 얹을 유튜브 댓글을 **찾고 · 고르고 · 배치하는** 기준.
`tools/jp-caption-writer.md` 가 캡션을 맡듯, 이 문서는 댓글을 맡는다.

**근거:** 추측이 아니라 `output/goodvibesongs/1xx/1xx댓글/` 에 쌓인 **채택 댓글 92건**
(100·101·102·103·105·106·107·108·109·110·111·112·113 — 사용자가 직접 골라 실제로 영상에 얹은 것)
에서 뽑았다. 예문의 좋아요 수는 그 스샷에 찍힌 실측값이다.

---

## 0. 대전제 — 실제 댓글만 쓴다

**없는 댓글을 지어내지 않는다.** 92건 전부 실재하는 유튜브 댓글이었고, 그 성격을 바꾸지 않는다.
`fetch-comments.mjs` 가 가져온 원문·좋아요·핸들을 그대로 쓰고, `render-comment.mjs` 는
그 데이터를 유튜브 다크테마 모양으로 **다시 그릴** 뿐이다. 창작은 이 파이프라인에 없다.

---

## 1. 제일 중요한 발견 — 좋아요는 U자 곡선

길이별로 좋아요를 늘어놓으면 **양 끝이 이기고 가운데가 죽는다.**

| 길이 | 예 | 좋아요 |
| --- | --- | --- |
| 아주 짧고 한 방 | 「当時「なんやこの衣装」現在「なんやこの衣装」」 | **7.5万** |
| 아주 짧고 한 방 | 「聞くタイプのプロテイン」 | **4.5万** |
| 아주 짧고 한 방 | 「台本のない夫婦生活が始まる」 | **4.9万** |
| 중간 길이 평범한 감상 | 「35歳男性の私、とてと聞いて涙が出るのはなぜ？」 | 314 |
| 중간 길이 평범한 감상 | 「口から音源やん」 계열이 아닌 밋밋한 칭찬 | 300~800 |
| 아주 길고 진심인 사연 | 자위대 파일럿 2차 불합격 사연 (7줄) | **1.7万** |

**고를 때의 함의:**
- **짧으면 반드시 "구조"가 있어야 한다** — 대구(当時/現在), 은유(プロテイン), 반전. 그냥 짧은 칭찬은 약하다.
- **길면 반드시 "진짜 자기 인생"이어야 한다** — 나이·직업·실패가 구체적으로 박힌 고백.
- **어중간한 감상문이 제일 약하다.** 「すごく良い曲ですね」류는 좋아요도 낮고 화면에서도 안 읽힌다.

화면상 이유도 같다. 하단 밴드는 440px뿐이라 **한 호흡에 읽히는 짧은 것**이 유리하고,
긴 사연은 예외적으로 "읽게 만드는 힘"이 있을 때만 값을 한다.

## 2. 아키타입 6종

`fetch-comments.mjs` 가 이 갈래를 자동으로 붙여 준다. 실제 채택 예문과 함께.

### ① 유머·밈 — 가장 강함
한 줄 은유나 대구. 좋아요가 압도적이고, 곡 분위기를 해치지 않으면 무조건 1개는 확보.

- 「聞くタイプのプロテイン」 (4.5万) — 듣는 타입의 프로틴
- 「当時「なんやこの衣装」現在「なんやこの衣装」」 (7.5万) — 시간 대구
- 「一生歌上手いなこの筋肉妖精」 — 별명 붙이기

**문형:** `聞くタイプの〜` / `当時「X」現在「X」` / `〜な件について` / `〜すぎる件`

### ② 감탄·실력
보컬·라이브 영상의 주력. 짧고 세게.

- 「口から音源やん」 (739) — 입에서 음원
- 「叫ぶように嘆くような歌い方は反則やろ」 (3577) — 창법은 반칙
- 「サビのハモリで鳥肌立った、何回も戻して聴いてる」 (268)

**문형:** `〜は反則` / `鳥肌立った` / `口から音源` / `〜やん・〜やろ`(관서벤=친근한 감탄) / `語彙力` / `えぐい`

### ③ 감정·위로 — 상호작용형이 특히 셈
듣는 사람을 **규정하고 말을 거는** 것이 핵심. 단순히 "울었다"보다 "우는 너는 지친 거야"가 훨씬 강하다.

- 「これ聞いて、ちょっと涙出ちゃう人はたぶん疲れてる、みんな優しく過ごそうね もちろん自分に」 (7315)
- 「スンスン好きな人は優しすぎて疲れてる人 今日もお疲れさま」

**문형:** `〜な人はたぶん〜` / `今日もお疲れさま` / `自分にも優しく` / `沁みる`

### ④ 사연·자기투영
나이·직업·실패가 구체적으로 박힌 고백. **길어도 된다.** 응원가·인생곡에서 폭발.

- 「"夢はもう見ないのかい？" って一発目で聞こえてきて、ギクってした大人は自分だけじゃないはず。」 (1641)
- 자위대 파일럿 2차 불합격 사연 (1.7万) — 111번 피날레의 메인

**문형:** `N歳〜の私、〜` / `〜のは自分だけじゃないはず` / `今になって刺さる`

### ⑤ 가사 지목 — anchor 붙일 후보
특정 구절을 지목하므로 그 caption `start` 초에 정확히 붙인다.

- 「汀さんの「君だよ君なんだよー」の部分じわーってきてテンション上がります。」 (1842)
- 「サビのハモリで鳥肌立った」

**문형:** `「가사」の部分` / `ここの〜` / `一行目` / `サビの〜`

### ⑥ 시의성·맥락
결혼·N주년·라이브 참전 등 바깥 사건이 곡에 얹힐 때만 성립. 유효기간이 있다.

- 「ドラマで結婚して現実でも結婚するとかどんなドラマだよ」 (4791)
- 「源さん結婚したから聞きに来た 同志がいっぱいいたようで嬉しい」 (2324)
- 「＿人人人人人人人人＿ ＞祝・結婚＜ ￣Y^Y^Y^Y^Y^Y^Y^￣」 (6443) — 아스키아트

### (보조) 반복 재생
범용이라 어디든 붙는다. 슬롯 채우기용.

- 「気づいたら3時間経ってた」 (6854) — **문형:** `気づいたら〜てた` / `無限リピート`

| 곡 성격 | 배합 | 비고 |

| 시의성 얹힌 곡 (107 恋) | 시의성 4 · 유머 2 · 가사지목 1 | 유효기간 주의 |

## 4. 거르는 것

- **어중간한 감상문** — 「良い曲」「最高です」류. 좋아요도 낮고 화면에서 안 읽힌다.
- **영어 댓글** — 타깃이 일본. (`fetch-comments` 가 기본 제외. 단 한자만 있는 아스키아트를
  영어로 오판하지 않도록 "라틴 문자 우세"로 판정한다 — 「祝・結婚」이 실제로 걸렸던 적 있음.)
- **스팸·홍보·URL**
- **곡과 무관한 논쟁·정치**
- **너무 긴데 좋아요는 낮은 글** — 화면만 먹는다.

---

## 5. anchor 붙이기

- **가사 지목형**은 그 caption 의 `start` 초에 붙인다.
- **⚠️ 타임스탬프(`1:06`)를 가리키는 댓글은 물어볼 것.** 그 시점이 어느 가사인지 모델이 알 수 없다
  (CLAUDE.md 규칙). `fetch-comments` 가 `needsAnchor: true` 로 표시해 준다.
- 나머지는 anchor 없이 두면 `prep-comments` 가 남은 슬롯에 균등 분배한다.

## 6. 도구 (표준 경로)

**이게 표준 경로다 (2026-08-31 확정).** 사용자가 레퍼런스 링크를 주면 → 수집·리스트업 →
사용자가 고름 → 렌더 → 편집에 얹는다. 사용자가 직접 스샷을 찍어 주는 경로도 그대로 살아 있고,
두 경로가 한 폴더에 섞여도 된다 — 렌더가 실제 스샷과 픽셀 단위로 맞춰져 있기 때문이다.

### ⚠️ 유튜브의 "인기 댓글순"을 믿으면 안 된다

유튜브가 주는 순서는 좋아요 순이 아니다. 답글 수·최신성·채널 하트까지 섞은 **참여도 랭킹**이라
좋아요 실수치와 크게 어긋난다. 星野源「恋」에서 실측한 값:

| 좋아요 순위 | 좋아요 | 유튜브가 보여준 위치 |
| --- | --- | --- |
| 1위 | **4.9万** | YT#11 |
| 3위 | 1.2万 | **YT#71** |
| 9위 | 4983 | **YT#86** |
| 14위 | 3492 | **YT#140** |
| 17위 | 3189 | **YT#146** |
| (유튜브 1위) | 4791 | YT#1 |

**유튜브가 1등으로 보여준 댓글이 4,791 인데 11번째 댓글이 49,000 이다 — 10배.**

그래서 `fetch-comments.mjs` 는 **넉넉히 긁은 뒤 좋아요로 다시 세운다.**
- `--pool` 이 정렬 전 후보 수 (기본 600). 얕게 긁으면 YT#140 같은 데 묻힌 고좋아요 댓글을 통째로 놓친다.
- 恋 기준 600 이면 상위권이 포화된다 (1200 까지 파도 순위 불변, 약 12초).
- 피드가 아직 남았는데 끊었으면 `⚠ 댓글이 아직 더 있는데 …에서 끊었다` 를 출력한다 → `--pool` 을 올린다.
- 유튜브 원래 순서가 보고 싶으면 `--sort youtube`.

### 댓글은 클립의 출처 영상에서만 오는 게 아니다

**중요 — 이걸 잘못 알면 도구를 잘못 만든다.** 댓글은 그 클립을 딴 바로 그 영상에서만
가져오는 게 아니라, **영상에 어울리기만 하면 완전히 다른 영상에서도** 가져온다.
(113 의 「Takaの声とikuraの声、こんなに合うと思わなかった」 412 는 그 컬래버 업로드에 없다.
같은 곡이라도 공식 MV / 라이브 / 커버 / 쇼츠가 전부 다른 댓글창을 갖는다.)

그래서 "출처 영상을 정확히 맞히는 것"은 목표가 아니다. **후보 풀을 넓게 모으고 고르는 것**이 목표다.

### 표준 절차 (작업 기준)

1. **곡명으로 검색**
2. **조회수 상위 3개 업로드**를 잡는다 — 조회수 많을수록 댓글도 많고 좋은 게 나온다
3. 세 영상 댓글을 **한 풀로 합쳐 좋아요순 정렬**
4. 기존 채택 댓글들과 **비슷한 느낌**의 것을 고른다 (위 아키타입·U자 곡선 기준)

`fetch-comments.mjs` 가 1~3 을 한 번에 한다. 4 는 사람/모델의 판단.

### ⚠️ 글로벌 곡(K-pop·팝)은 원곡 MV 에 일본어 댓글이 없다

정국「Seven」공식 MV 상위 **1,300건을 긁어도 일본어 댓글이 0건**이었다. 글로벌 릴리스는
댓글창을 영어권이 장악해서 「Anyone in 2024?」류가 상위를 전부 먹는다.

**그런 곡은 일본어 업로드를 찾아야 한다** — 검색어에 `日本語字幕` / `和訳` / `歌ってみた` 를 붙인다.

```bash
node tools/fetch-comments.mjs "Seven ジョングク 歌ってみた" --must "Seven" --limit 12
#   → 【日本語字幕】 Jung Kook- Seven  에서 1.1万 짜리 일본어 댓글이 바로 나온다
```

일본 아티스트 곡(back number, 米津玄師 등)은 원곡 MV 그대로 가면 된다 — 이 문제는 해외곡 한정.

**ⓘ 댓글이 꺼진 영상이 섞여도 괜찮다** — 조회수 상위 3개에 「- Topic」 자동생성 채널이 끼면
댓글이 꺼져 있는데, `fetch-comments` 가 그 영상만 건너뛰고 나머지로 계속 간다.

**ⓘ 언어 필터** — 일본어(가나·한자)가 하나라도 있으면 통과, 없으면 라틴·키릴·한글·태국어·아랍
글자가 3자 이상일 때 제외한다. 순수 기호 아스키아트(「＿人人人＿ ＞祝・結婚＜」)는 남는다.
해제하려면 `--allow-en`.

**⚠️ 조회수만으로 고르면 다른 곡이 올라온다.** "ONE OK ROCK with YOASOBI Wherever you are" 를
조회수순으로 잡으면 같은 밴드의 **「We are」(5,700만)** 가 1위로 올라와 풀을 장악한다 —
「喉の調子が…」 처럼 그 곡 얘기만 잔뜩 나온다. 그래서 **제목에 곡명이 든 영상만** 남기는
게이트가 들어 있다(`--video` 면 사이드카의 곡명이 자동, 아니면 `--must "곡명"`).

```bash
# 1) 수집 — URL·곡명·영상번호 셋 다 됨. API 키·yt-dlp 불필요 (유튜브 내부 API 직접 호출)
node tools/fetch-comments.mjs --video goodvibesongs/113 --limit 30
#   → 사이드카에서 곡명 유도 → 조회수 상위 3개 → 합본 → 좋아요순

node tools/fetch-comments.mjs "米津玄師 Lemon" --must "Lemon" --limit 30   # 곡명으로
node tools/fetch-comments.mjs "https://youtu.be/A" "https://youtu.be/B"    # 영상 직접 지정(여러 개)
#   --spread N  검색어 하나당 긁을 업로드 수 (기본 3)
#   --must "곡명"  제목에 이 문구가 든 영상만 (다른 곡 유입 방지)
#   합본이면 각 댓글 밑에 └ 로 출처 영상이 표시된다
node tools/fetch-comments.mjs "星野源 恋" --limit 30 --min-likes 100 --out /tmp/koi.json
#   좋아요 실수치 내림차순 + 아키타입 자동 태깅 + needsAnchor 표시
#   각 행의 YT# 가 유튜브 원래 위치 — 순번과 벌어질수록 유튜브 랭킹이 어긋난 것

# 2) 렌더 — 수집한 진짜 댓글을 유튜브 다크테마 PNG 로
node tools/render-comment.mjs --from /tmp/koi.json --all --outdir ./렌더 --scale 1 --soft2x
#   규격은 채택본 **107장 전수 실측**에 맞춤 (2026-08-31 교정 — 그 전엔 눈대중이라
#   배경·핸들 크기·줄간격·아이콘 모양이 전부 틀려 있었다)
#   프사는 실사진(fetch-comments 가 avatarThumbnailUrl 을 같이 담아 온다)
#   <이름>.geo.json 사이드카에 프사·핸들 좌표를 정확히 내보낸다

# 2b) 검증 — 고쳤으면 반드시 코퍼스와 대조. 전 항목 ✓ 여야 한다
node tools/measure-comments.mjs --compare ./렌더/01.png

# 3) 비식별화 — 기존 도구 그대로. 자동 측정 대신 사이드카 좌표를 넘긴다
node tools/blur-comments.mjs 렌더/07.png --out 07.blur.png \
  --avatar-x 0 --avatar-y 13 --avatar-w 64 --avatar-h 64 \
  --nick-x 90 --nick-y 14 --nick-h 29 --handle-end 241
```

**왜 좌표를 넘기나:** `blur-comments` 의 자동 지오메트리 측정은 *실제 스샷*에 맞춰져 있어
합성 렌더에서는 빗나갈 수 있다. 그릴 때 아는 좌표를 그대로 주면 이 문제가 사라진다.
`prep-comments` 를 쓸 거면 좌표를 manifest 각 항목에 넣어 두면 된다(자동측정을 건너뛴다).

## 7. 한계 — 아직 모르는 것

- **탈락 사례가 없다.** 코퍼스는 채택본 92건뿐이라 "왜 뽑았나"는 알아도 "왜 버렸나"는 추정이다.
  앞으로 후보를 추릴 때 **버린 것도 몇 개 같이 남겨 두면** 기준이 훨씬 정확해진다.
- **성과 데이터가 없다.** 어떤 댓글 배합이 실제 조회·저장으로 이어졌는지는 연결되어 있지 않다.
- 렌더는 실제 스샷과 **거의** 같지만 100%는 아니다(폰트 힌팅·아이콘 두께). 프사·닉네임이
  어차피 블러 처리되고 하단 밴드에서 축소 표시되므로 실사용 차이는 확인된 바 없다.
